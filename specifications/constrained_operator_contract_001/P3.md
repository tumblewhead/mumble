# P3: conditional memory schedule with validation before mutation

This is a proposed packed-C schedule with mathematical and operational premises,
NOT an implemented allocator, bounded-WCET kernel, deployment memory certificate,
or universal rollback mechanism. It refines A3/A4 for anticipated deterministic
validation failures. Keep original 34-feature likelihood root U, 312B response,
full joint inference, original prior/support and all source identities. Input
admission and generation synchronization precede the operations below.

## Two-pass row insertion without a duplicate history factor

U is upper triangular W by W. A new normalized evidence row x is appended using
Givens rotations. At step k, compute h=hypot(Ukk,xk), c=Ukk/h,s=xk/h (if both
zero use c=1,s=0). For j>=k compute, from the OLD entry and old scratch xj,

    candidate_Ukj = c*Ukj+s*xj,
    next_xj      = -s*Ukj+c*xj.

Canonicalization conventions, operation order, rounding mode and validation must
be identical between passes. Treat the displayed formula as a specified scalar
algorithm, not an assurance of arbitrary BLAS bitwise equivalence. The first pass
reads U without mutation, carries only x, validates every candidate entry, and
reduces any required streamable global validation statistic. Candidate response
and scalar metadata are prepared separately. Admission/validation failures keep
the complete old generation unchanged and the identified input unconsumed.

The second pass reconstructs the same initial x from unchanged old response,
staged response and the held input. It repeats the scalar operations and writes
candidate_Ukj in place, reading each old entry before overwriting it. Row k is
never read again by later rotations: they need only future rows and scratch x.
Induction on k,j proves identical arithmetic inputs and hence bit-identical
candidate outputs to the first pass, under deterministic floating arithmetic and
unchanged environment/configuration. No full candidate factor or rotation log is
needed. Then commit staged response, count, normalizer and generation together.
In exact arithmetic orthogonality proves Unew^T Unew=Uold^T Uold+x0*x0^T;
floating backward error and finite-range lifetime remain separate obligations.

Premises are significant:
- The row generator is deterministic and can re-emit the identical row using the
  retained input and staged/old response, with bounded counted scratch.
- All required rejection predicates are decidable in the read-only pass with
  the counted state. A later dense validation/solver cannot be assumed free.
- Readers/checkpoints/interrupt consumers cannot observe tentative bytes. Commit
  bookkeeping is synchronized; the admitted input and configuration stay frozen.
- After dry-run success, no ordinary data-dependent rejection remains in replay.
  Determinism excludes hardware corruption, altered rounding, asynchronous state
  mutation and environmental allocation failure, which need the fault path below.

This is two evaluations of one row, ONE committed evidence contribution. Failed
prevalidation retries use the same unconsumed identity. A consumed prefix may be
re-solved but its row may not be added twice. Preparing state still propagates
all actual intervals; a rejected measurement does not justify skipping time.

## Fault and reset edges: do not claim rollback after overwrite

Before mutation, revoke current read permission via a synchronized updating
state. Successful publication names the new complete generation. An interruption,
fault, unexpected post-mutation check failure or uncertain completion keeps that
state quarantined; no readout may use the partially updated factor. Old publication
can at most remain explicitly historical. There is NO complete old factor to
restore. Unfinished work cannot retry normally as if the input were unconsumed.
Recovery must establish known ownership from a qualified checkpoint/replay or
reinitialize from a public aged-cell support, exposing the loss of information.
Reset/power-loss durability and useful recovery are not proved by this schedule.

This satisfies A4's conditional commit/reject/quarantine safety alternatives,
not uninterrupted availability or arbitrary-fault rollback. If deployment requires
preserving the last usable full factor through mid-write failure, a checkpoint,
journal or other qualified redundancy must be paid for. Its bytes are not hidden
in the proposed savings. The first-pass validation proof does not discharge
stack overflow, interrupt timing, C aliasing or corruption detection.

## Rowwise joint inference without a 34 by 16 Jacobian

For feature vector phi(theta) and derivative rows d_j=D phi_j, generate

    r_i = sum_(j>=i) Uij*phi_j,
    B_i = sum_(j>=i) Uij*d_j.

Keep phi (34 doubles), one emitted derivative row (16), and one accumulated
augmented row [B_i,r_i] (17). Recompute d_j as needed; no materialized 34x16 Dphi
or B is necessary. QR-insert these rows and the original prior residual/Jacobian
rows into a packed 17x17 augmented root S (153 doubles). Then exactly

    S^T S = [P, g; g^T, ||r_total||^2]

where P is full joint local GN precision and g the full gradient, including prior.
For S=[R,c;0,rho], P=R^T R, g=R^T c. Solve R*step=-c without forming normal
matrices; retain all cross terms. If P is singular, a solve needs explicit
unresolved/rank handling, not invented diagonal information. Repeated derivatives
trade CPU for SRAM; exact-arithmetic equality does not imply bitwise equality
with a dense GEMM/QR path or a target WCET improvement.

In normalized fixture coordinates the prior is diagonal/identity, as before.
A general prior retains its full root and correct transformed derivatives. Do
not diagonalize it to obtain the fixture storage figure. Damping, if used, is
solver workspace/algorithm only, never evidence or reported posterior precision.
Trial root/cost can overwrite inference scratch because committed U is read-only;
recompute the current linearization if a rejected trial needs it again.
Current theta, trial theta and step are distinct named buffers. No indefinite
retention of scratch pointers by publications is allowed.

For a scalar application query with gradient gq, solve R^T y=gq and compute
variance=y^T y. Two queries' local covariance is y1^T y2. Recompute gradients
and stream covariance entries if necessary; no independence assumption or full
16x16 inverse is needed. A response query can carry five dynamic states and their
5x16 sensitivities (85 doubles) while static theta stays separate. This is an
interface/space allowance, not a port of the existing forecast routines. A
multi-horizon output/plot or full covariance retained by a caller needs its own
storage; streaming output is a premise of these counts.

## Concrete named lifetime ledger

All values are binary64, with packed factors; tables charged to SRAM. Existing
persistent ledger is 6216B: factor4760,response312,centres40,halfwidths40,
calibration112,count8,assumed digest32,normalizer8,prior mean128,diagonal prior
scale128,projection tables72+432,nodes24,rate cache120.

Serialize streaming, fitting and query phases. The same scratch arena is reusable
only after every branch's final reader; no live inference may overlap streaming.

| Phase | Additional named live objects, bytes | Persistent + scratch |
|---|---|---:|
| Stream prepare/validate/replay | response312, sample40, QR row272 | 6840 |
| Joint fit | augmented root1224, features272, derivative128, augmented row136, current/trial/step384, cost/scalar allowance64 | 8424 |
| Scalar query | augmented root1224, theta128, state/sensitivity680, two solves256, result8, scalar allowance56 | 8568 |

The stream saving versus the old named layout is4760B; fit saving3488B versus
11912B. The old report had no comparable full query phase, so do not claim a
query saving. Maximum of these SERIAL phase subtotals is8568B, leaving1672B
unallocated below10240. This is not measured free RAM. A generic packed16D prior
root adds960B relative to128B diagonal scale, yielding9528B and712B unallocated.
No ROM-placement or discarded uncertainty savings are credited.

Excluded/unqualified: actual response/feature-generator temporary requirements,
alignment, stack/library frames beyond explicitly named scalars, cache/registry
and transaction synchronization metadata beyond the assumed digest/count, input
queue/ISR nesting, application/output buffers, fault recovery/checkpoint storage,
finite-precision certificates and their workspace. Solver/cadence concurrency,
queue length and deadlines require worst-case timing; doubled insertion and
recomputed derivatives may make serialization infeasible at the required rate.
The maximum sample rate/CPU share and recovery guarantee remain open inputs.
This named schedule fits arithmetically; complete subsystem feasibility is OPEN.

## Required implementation gate

Before crediting savings: port the two-pass insertion and rowwise solve in isolation;
compare successful states/rows against a copied-factor scalar reference; reject
all anticipated prevalidation faults without mutation; quarantine every injected
mid-write fault and refuse stale handles; test duplicate/gap/reset ownership;
compare joint P,g,cost, steps and transported covariance against dense QR; bind
compiled layout, stack, helpers and timing to the full lifecycle. Independent
optimization review is mandatory. The accompanying Python checks are finite
mathematical/control witnesses, not this C implementation or lifetime gate.
