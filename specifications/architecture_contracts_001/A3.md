# A3 — Object ownership, lifetimes and memory reuse

## Interface, premises and invariant

Each logical object has a semantic type, immutable-generation identity, byte
extent/alignment, owner, permitted readers and final release event. Borrowed
configuration/priors cannot be overwritten by consumers. Trial state and trial
evidence are private until commit. Publications are immutable snapshots or checked
generation handles; a consumer cannot retain an untracked raw pointer into scratch.

The lifetime graph includes normal computation, failed validation, rollback,
diagnostic/publication, checkpoint, reset/restore and all admitted interrupt or
concurrent readers. Old committed state remains live through every path that can
need it. A successful-path last read alone does not terminate its lifetime.
Byte ranges may alias only if their lifetimes are disjoint on every admitted path,
or an explicit in-place read/write-version proof permits the overlap.

## Conditional theorem and proof

Assume a concrete mapping of logical bytes to valid aligned physical regions,
with no out-of-bounds/overflow/type-alias violation and synchronized accesses.
Assume distinct simultaneously live logical bytes are not mapped to overlapping
physical bytes, except where a proved alias denotes the same intended value.
Every byte is initialized before being read. Maintain the invariant that each
initialized live logical byte equals its physical representative.

Initialization establishes the invariant. A read observes that representative.
A write changes the named logical version and its representative; the nonoverlap
premise prevents changing another live value. Release removes a value only after
all its admitted readers have finished. Reallocation then initializes the new
value without destroying an accessible old one. Induction over all accesses
proves ordinary and recovery readers observe the separate-storage program's
values. This is reviewed K4's refinement applied to the architecture's objects.

For in-place updates, each later read of an overwritten byte must explicitly
intend the new version or use a retained old copy. An algebraic state identity
does not prove this ordering. A graph that needs rollback at event5 cannot release
the old state at event2 merely because the successful path last used it then.

## Failure, interfaces and resources

If the successor does not fit reserved storage or alias safety cannot be shown,
do not partially reuse the committed object's storage. Reject preparation without
consumption, or quarantine under A4 if mutation/consumption has already occurred.
Do not allocate an unbounded emergency backup or silently discard old evidence.
Publication handles must fail closed after generation revocation; retaining a
copy gives only a statement about its named historical prefix, not current authority.

This contract requires ownership correctness, not a particular double-buffering,
arena, journal or registry implementation. Power-loss durability and arbitrary
corruption need separately admitted storage/fault models. A C-level proof must
also discharge effective type, alignment, pointer provenance and synchronization;
a mathematical interval-liveness drawing is insufficient.

Before acceptance: enumerate success, every failure edge and recovery readers;
show a byte layout and maximum overlap; inject failures before/after each staged
write/commit/publication; test retained handles and attempted alias reuse. A test
that overwrites a rollback value before its final possible read must fail. Bind
the verified allocator/layout to A8 including registry, alignment/padding, stack,
ISR nesting, backup and serialization storage. No shared arena is implemented or
qualified by this specification; source-level payload totals are not total SRAM.
