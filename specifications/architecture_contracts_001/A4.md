# A4 — Evidence ownership, chronology, authority and recovery

## Abstract state and transition outcomes

A committed generation binds the source/epoch/prefix, chronological physical
state or reach relation, joint evidence representation, unchanged original prior
identity and approximation ledger. Its published readout has an independently
recorded prefix/guarantee/horizon. Consumed and published prefixes are distinct.
Input admission checks source, nonce/order, interval/configuration and validity
before mutation. A rejection is not an observed physical interval magically removed.

For each admitted operation exactly one terminal outcome is allowed:

1. Commit a complete validated successor at its actual consumed prefix. Query
   authority may remain unresolved even when evidence consumption succeeds.
2. Leave the complete previous object unchanged, mark the input unconsumed,
   and preserve its existing quarantine/authority state. Retry only that identified
   unconsumed input; old publication remains historical at its old prefix.
3. Quarantine and revoke affected readout authority before any reader can treat
   inconsistent bytes or unknown consumption as current. Recovery must establish
   actual ownership before replay; uncertainty is not permission to duplicate data.

Each observation's physical transition occurs in order. Each retained likelihood
contribution occurs once. A posterior derived from a prefix cannot be added to
that prefix as independent evidence. Overlapping detector windows are context,
not overlapping evidence ownership. Missing intervals require known replay or
qualified uncertain input/time propagation; substitute-zero current is forbidden.

## Conditional theorem and proof

Initially the object is validated or quarantined. Assume complete successors
satisfy all common invariants and commit/authority revocation is synchronized with
readers. Induct over operations. Outcome1 produces a consistent owned prefix;
any new authority binds that prefix and A5's valid query guarantee. Outcome2
preserves the old invariant and cannot claim the unconsumed interval. Outcome3
permits no authority from partial state. Therefore every authorized publication
derives from a consistent matching prefix. Synchronization extends this endpoint
argument to intervening readers. This instantiates D7; transaction code and
publication synchronization must still establish its premises.

Ownership provides a disjoint ordered partition of retained observations. With
a fixed row generator and feature semantics, partitioning the sum of per-record
likelihoods preserves the same mathematical evidence. K6 supplies that grouping
identity. It does not imply bitwise QR equality, preservation under changing
linearization anchors, or safe deletion of uninteresting-looking samples.

## Recovery, availability and reset obligations

Readout failure after complete consumption leaves that input consumed. Recovery
may re-solve the same evidence; it must not add it again. A computational rate-box
exit is representation failure, not physical exclusion. More iterations, a new
anchor, basis migration or a broader support requires its own A6 validity and A8
cost argument. The observed82-round witness establishes no universal recovery cap.

Define a recoverable scenario class, maximum attempts, service-time budget and
post-recovery excitation/power assumptions. If restoration finishes within R and
qualified A5 query production within another T, service resumes within R+T by
addition. Useful availability requires proving both premises, not declaring every
failure outside the class after observing it. Outside that class return explicit
unresolved/quarantined status and use a separately qualified system fallback.

After reset, an older checkpoint is historical. Replay known missing observations
once or propagate their qualified uncertainty before current authorization. With
lost SRAM/history, initialize from a public support valid for an aged cell; do
not pretend it is a new battery. Preserve lifetime risk accounting through reset
or use another valid whole-life risk construction (D3). A checksum alone neither
proves a physical state current nor guarantees integrity under all fault classes.

## Acceptance witnesses

Enumerate source/nonce duplication, gaps, irregular dt and rate switches; failures
at admission, evidence update, validation, commit, query and publication; reset
before/after consumption; stale handles and restore identities. Inject each failure
and verify ownership and authority outcomes, including unresolved-but-consumed.
Run both useful recovery and permanent-fault controls. Specify the actual fault,
interrupt, power-loss and storage models before claiming unattended recovery.
No concrete recovery controller or deadline is implemented/proved here.
