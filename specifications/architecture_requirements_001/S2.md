# S2: storage and finite-horizon feasibility bounds

This is accounting under explicit representation/platform premises, not a claim
that any listed candidate is accurate, stable or executable on the target.

## Partitioned tensor coefficient count

Under stationary A0, use one tensor-product polynomial table per independent
augmented Gram coefficient function, with degree at most d in each of its distinct
shape arguments. Include all monomials/tensor basis functions for that table,
with no cross-table sharing, sparsity or symmetry beyond A0's upper triangle.
Let n=d+1. A function of j arguments has n^j coefficients by counting Cartesian
products of the n one-dimensional basis functions. A0 gives ten constants,
33 one-argument,23 two-argument and12 three-argument functions. Therefore

    N(d) = 10 + 33n + 23n^2 + 12n^3.

| Degree per argument | Coefficients | Binary64 coefficient bytes | Remaining of10240B |
|---|---:|---:|---:|
| 0 | 78 | 624 | 9616 |
| 1 | 264 | 2112 | 8128 |
| 2 | 640 | 5120 | 5120 |
| 3 | 1278 | 10224 | 16 |

The multiplication by8 assumes8-byte coefficient storage. All metadata, endpoint
transport functions, original prior/support, numerical scaling/error ledger,
multiple domains, sample buffers, solver work, registry/caches, transaction backup,
alignment, stack and ISR use are **additional**. Degree0 is constant in shapes,
not a continuous unknown-shape inference solution. Degree1/2 fit only this raw
subtotal; no useful approximation is established. Degree3 cannot accommodate even
the known40-byte five-shape numeric record in addition to these coefficients,
let alone a complete subsystem, under this particular storage scheme. A more
sparse, shared or lower-precision representation has different premises/counts
and requires new error analysis. This is not a universal cubic impossibility.

The existing768-byte fixed-shape subtotal contains624factor bytes,72response bytes,
40shape bytes and32miscellaneous numeric bytes. It conditions away shape uncertainty
and is not added wholesale to the table, since some quantities overlap. Likewise
table entries alone do not provide an update recurrence: the state needed to update
and transport them must be derived and counted. A full112x112 packed binary64 H7
factor is112*113/2*8=50624B, already exceeding10240B before other memory.

If M_other is the proved maximum additional simultaneous SRAM use, a necessary
condition is `8*N(d) + M_other <= 10240`. Lifetime-safe reuse can lower M_other
only under A3; a typical RSS or average live set cannot. A sufficient memory proof
needs a concrete complete layout and all admitted call/interrupt paths.

## Counters and nominal processing ceilings

Choose the conservative finite design envelope H=10*366*86400=316224000seconds.
This deliberately exceeds ten usual calendar years. For fixed F_s and no extra
initial sample the interval count is at most ceil(F_s*H); reserve one more identifier
if acquisition also records an initial endpoint. At35Hz this is11067840000intervals
(34unsigned bits); at100Hz31622400000 (35bits). A32-bit per-sample counter is
therefore insufficient at either rate. Nonwrapping64-bit logical sample counters
cover these example rates and horizon. Maximum supported F_s must still be frozen;
transaction/generation/retry/query counts require independent bounds. A64-bit
counter is not a persistent unique boot identity or a lifetime risk ledger.

With clock f=16000000Hz and estimator fraction rho of useful CPU service, the
average necessary ceiling is `C_amortized <= rho*f/F_s` cycles per interval.
At rho=1, the ceilings are approximately457143cycles at35Hz,320000 at50Hz,
and160000 at100Hz. Include acquisition, amortized block/query/refresh/recovery,
cache misses and reporting charges assigned to the estimator. Round down for a
hard integer budget. rho is an external platform allocation, not assumed to be1.
These ceilings are necessary average conditions only. A8's service, blackout,
arrival/backlog and deadline premises are additionally required for hard timing.

## Resource acceptance

Compare candidate families on total simultaneously live bytes, maximum work,
likelihood/transport bounds and useful-query availability together. Do not promote
the smallest coefficient subtotal if its update/recovery state is unbounded or
it loses uncertainty. The counter and table arithmetic is independently checkable;
no target benchmark, full SRAM claim or long-run stability proof follows from it.
