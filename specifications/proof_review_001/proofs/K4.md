# K4 — Storage reuse with recovery readers

## Model and assumptions

The abstract program has separately stored logical objects (including generations
of mutable objects). Reads refer to initialized bytes of a particular generation;
writes specify the generation and byte offsets. All accesses and allocation/
release events have defined order in each admitted execution. Fault and recovery
accesses, serialization, interrupts and retained pointers are included.

A candidate maps logical objects to physical byte ranges. Assume:

1. Each range has sufficient capacity, valid alignment and a valid language-level
   type/provenance/aliasing interpretation. Required initialization is preserved.
2. If ranges overlap, the final access/release of one lifetime happens before the
   first allocation/write of the next lifetime on **every admitted execution**.
   Merely finding one nonoverlapping schedule is insufficient. No retained access
   to the earlier generation is possible after release.
3. Allocation/address identity is not otherwise observable, or its observations
   are explicitly related by the interface contract. Concurrent accesses are
   synchronized or have a semantics that admits this ordered access model.
4. The mapping introduces no unmodeled faults or changes to externally observable
   effects. Hardware corruption and resource exhaustion need separate contracts.

## Value-preservation theorem

At every access, candidate reads return the same logical byte values as the
separate-storage program. Maintain the invariant that every initialized byte of
every live logical object equals its mapped physical byte. It holds after matched
initialization. A read preserves it and returns the same value. A write updates
the same logical byte and physical byte; assumption 2 ensures it cannot overwrite
a byte of another live overlapping object. Allocation initializes new bytes as
specified after earlier occupants are no longer accessible. Release removes an
object from the invariant without requiring its old value to be retained.
Induction over accesses proves the assertion for every admitted finite trace.

If the abstract transition function depends only on these values and the same
external inputs, its ordinary and recovery computation sees identical values.
Observable pointer identities, timing and new faults are explicitly outside this
value theorem unless separately matched by assumptions 3–4.

## In-place specialization

Within one operation, overwriting an old version is sound if every later read
of any overwritten byte either (a) is meant to read the new version or (b) reads
an independently retained old copy. To prove it, use the same access induction
with the specified per-read version. An algebraically equivalent output formula
alone does not establish read-before-overwrite ordering.

## Recovery counterexample and scope

Let an old state be last read on the successful path at time 2, but needed for
rollback at time 5. Reusing its bytes for a trial at time 3 preserves the normal
path but destroys the rollback value. The true lifetime ends at 5, not 2; assumption
2 fails. Thus a liveness graph must include all permitted recovery/fault readers.

This is a logical storage refinement proof under explicit C/concurrency premises,
not a complete C memory-model proof. Stack, scratch, registry metadata, padding,
backups and cache payloads all remain in the target resource accounting.
