# K3 — Pure graph execution and memoization

## Exact graph theorem

Consider a finite directed acyclic graph of single-assignment values. Each node
v applies a total deterministic function f_v to its ordered predecessor values
and immutable configuration c_v. Totality means termination with a declared value;
errors, if represented as values, are propagated identically. All external leaves
are fixed for this invocation. Functions have no unmodeled observable side effects.

Every topological evaluation yields the same values. Proof: induct on a node's
longest predecessor-path length. Leaves are fixed. Given fixed predecessor values,
the node receives the same ordered arguments and configuration, so determinism
fixes its value. Every finite DAG node has finite depth, completing the induction.
Different schedules can have different time/memory use; those need separate bounds.

For streaming state, each generation of mutable data must be an explicit versioned
value or serialized effect. Read-after-write, write-after-read and write-after-write
dependencies cannot be omitted. This theorem concerns the resulting finite graph
per invocation; it does not permit temporal row generation to be reordered.

## Exact cache theorem

Let z contain all arguments, kernel version and configuration relevant to f.
A cache key K is sufficient if K(z)=K(z') implies f(z)=f(z') in the declared
observable value semantics. Argument equality is a sufficient, stronger condition.
Assume a hit returns exactly f(z') from a completed evaluation, that cache storage
has retained that value, and the sufficiency implication holds at lookup time.
Then returning the hit equals f(z), by substitution. Replacing any number of
nodes with such hits preserves all graph outputs by the graph induction.

For bitwise claims, values and the sufficiency condition use exact observable
representations; signed zero, NaNs and arithmetic environment must be treated
consistently or excluded by a proved domain. Numerical equality alone may not
be sufficient. A digest match requires full key validation or proven collision
freedom on the admitted domain. Pointer reuse and version wrap do not imply
argument equality. Concurrent lookup must see an atomic consistent key/value
generation; synchronization and memory integrity are premises.

Kernel side effects (source consumption, counters, errno, floating-point flags,
I/O, failure reports) require their own once-only transition semantics. If caching
skips an observable effect, the pure theorem does not apply. A valid error-valued
cache must not relabel failure as a validated estimate. Extra memory-fault paths
and timing-induced faults require a separate full-machine refinement argument.

## Approximate-key theorem

In a normed input/output space, assume f is L-Lipschitz on a bucket, both query z
and representative z' are in that same bucket, and ||z-z'||<=d. If a stored
representative value y' satisfies ||y'-f(z')||<=eta, then

    ||y'-f(z)|| <= ||y'-f(z')||+||f(z')-f(z)|| <= eta+Ld.

Here z must include every changing numerical dependency; discrete version/config
changes must match exactly or receive a separately justified comparison bound.
An externally chosen bucket center outside the proved region is not covered.
Propagate this defect at every use, including derivative outputs. It does not
justify limiting physical batteries to codebook nodes or assuming cache errors
are independent measurement noise.

## Scope

The graph/cache conditions are implementation obligations. Registry size, hit
rate, invalidation latency, worst-case cycles and guard costs are not established
by functional equality. This is not proof of a particular Mumble graph executive.
