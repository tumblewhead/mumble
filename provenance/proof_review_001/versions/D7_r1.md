# D7 — Transactional containment and autonomous recovery

## State and fault contract

Each committed object contains a consistent evidence prefix n, physical carried
state, likelihood representation and configuration/epoch identity. A publication
is an immutable readout with a query certificate tied to that identity and a
specified validity boundary/horizon. Old publications are not implicitly current.
Consumers obey those identity, expiry and revocation semantics.

Assume every admitted update/fault path terminates in one of:

1. Commit one complete valid successor object, with each new observation owned
   once and its physical transition applied in order.
2. Preserve the entire prior committed object and mark any outstanding input
   unconsumed, so a correctly identified retry cannot duplicate evidence.
3. Enter quarantine and invalidate affected publication authority before any
   reader can observe partially modified state as valid.

Publication and invalidation are synchronized with mutation: no reader can race
a partial update, mismatched epoch or half-written certificate into authorization.
Faults during publication, reset and restore are included in the admitted paths.
Arbitrary undetected corruption is outside this contract unless the fault model
and implementation separately establish detection/containment.

## No-partial-publication theorem

Assume initially the committed object is valid or the machine is quarantined.
Induct over completed operations. In case 1 the successor is valid by premise
and may publish only its matching validated readout. In case 2 the old object
remains valid; it can publish only for its actual unchanged boundary, not as a
readout of outstanding unconsumed input. In case 3 synchronization/invalidation
prevents authorization from affected partial state. These cases maintain the
invariant that every authorized publication comes from a matching complete
object and validated certificate. The synchronization premise extends the result
to readers between operation endpoints. Without it endpoint induction is not enough.

A failure after successful consumption but during query is a distinct case:
retain the complete committed evidence prefix and mark its readout unresolved.
Do not label the consumed block unconsumed or retry it as fresh evidence. This
may be represented as case 1 without new authorization, or quarantine of readout
authority. Publication failure is not synonymous with observation rejection.

## Autonomous recovery theorem

Define a qualified recoverable fault class and assume faults cease for a specified
recovery interval. Suppose a verified recovery controller uses at most r attempts,
each with a proved service-time bound, and on this class reaches by time R a valid
initialization/restore state satisfying the containment premises. Suppose further
that informative viable-power/sensor/use conditions thereafter guarantee useful
query authorization within time T under that same scenario contract. Then useful
operation resumes within R+T: the first premise restores the containment invariant
by R; the second supplies its authorization by another T. This is composition of
two concrete bounded-recovery obligations, not a derivation of them from retries.

Outside the recoverable class, bounded attempts may end unresolved/quarantined.
This is fault containment, not universal availability. A system fallback action
needs its own voltage/power qualification; the estimator cannot create energy
or promise service after permanent sensor failure.

## Reset, stale state and scope

Restoring an older prefix requires once-only replay of known gaps or qualified
uncertain propagation before current authorization. SRAM loss requires a public
initial support valid for an aged cell. Statistical lifetime risk cannot restart
from zero without a qualified reset-accounting rule. Reset/configuration identity
and any checkpoint integrity checks are premises, not proof from a checksum alone.
Certificates do not remain valid through subsequent faults merely because they
were valid at publication; consumers must honor the declared fault/expiry policy.

The known H7 field-flush fault can mutate response/count before QR succeeds; its
backend does not yet meet the complete contract above. Selected campaign exception
containment is weaker. No current backend, recovery controller, persistence layer
or unattended deployment is certified by this generic theorem.
