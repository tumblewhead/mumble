# Compact campaign recording for long runs

The campaign now supports `--recording compact`: 2,000 fixed time bins retain
means, extrema and counts, while full joint estimator/plant/controller/workload
checkpoints support exact local replay. Every observation still reaches the
unchanged estimator. Independent load and noise seeds are preserved.

This integrates the earlier uncommitted recorder with the embedded workload and
labeled plots. Incoming sources and their original diffs are archived in
[incoming/](incoming/) with hashes in [incoming.json](incoming.json). No canceled
large-checkpoint ancestry was imported. Generated runs remain local.

[Qualification](qualification.json) records 68 distinct targeted tests, the core
suite (18 C executables and 12 Python tests), a four-hour matched-input smoke,
and a three-hour full-resolution debug replay. The first suite had67tests; the
16-test follow-up includes the additional explicit-window test and repeats all
compact/workload controls after the final replay changes. Plot caption changes
have a separate four-test follow-up. Original attempts remain untouched.

Full versus compact observations/truth hashes, final joint messages, complete
score dictionaries, charger state and workload summaries matched exactly. The
three-hour debug window reproduced all540,000samples, estimator traces and final
joint messages exactly. Both individual and labeled summary plots are supported.
The plotting-only final caption change identifies compact mean/range traces.

The measured four-hour compact case used16.96MB including its individual plots,
versus287.51MB for full recording. Its summary NPZ was6.94MB and hourly checkpoint
NPZs were at most16.2kB. Extrapolating that checkpoint size to6,000hours yields
97.1MB of checkpoint NPZs, plus fixed summaries, plots, metadata/index and shared
sources. **Allow about0.5GB per case** as a conservative planning estimate, not a
quota. The uncompressed numeric estimate is241.3MB per case:8.544MB summaries plus
232.76MB checkpoint contexts. Debug intervals require separate raw-output space;
the three-hour example used148.56MB including plots and event logs.

This sizing target has not been simulated end to end. Counter/binner tests use
6,000-hour indices at35/50/100/500Hz, and a C ABI probe advances counters beyond
32bits; they do not qualify long-term battery estimation or coverage. CPU work
still scales with samples. Event CSVs are omitted in compact campaigns, replaced
by bounded counts/digests; selected event detail can be regenerated by replay.
Checkpoints grow with duration and do not resume aggregate campaign scoring.

See the [campaign guide](../../experiments/foster_campaign_001/README.md) for
6,000-hour commands and `--debug-start-hour` / `--debug-stop-hour`. Replay requires
the recorded source, binary and runtime identities. Default recording remains
`full` for compatibility; explicitly select `compact` for long campaigns.

The C core still uses19416B of context and has no M23 timing qualification. This
change does not repair uncertainty overconfidence or qualify aging behavior.
