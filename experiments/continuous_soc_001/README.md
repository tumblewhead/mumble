# Continuous SOC transport and four-hour history trials

The carried-SOC grid obstacle is repaired well enough to move from local
precision work to useful stream behavior. Two four-hour, 35 Hz controls now
complete with a fixed 729-hypothesis history. Binary32 log weights preserve
the binary64 reference well below the application's preferred scales of
0.5% relative capacity error and 0.5 SOC percentage points. The earlier
fixed-range log16 encoding runs out of range after 4 minutes 32 seconds.

This is an end-to-end **reduced-model history diagnostic**, using observations
generated by the existing C battery recurrence. It is not yet a history
provider integrated into the original rolling optimizer, a complete M23 memory
fit, or evidence of ten-year stability.

## Repair and local qualification

Barycentric deposition of a translated SOC point onto a grid adds artificial
variance `h² f(1−f)` at each fractional grid crossing. Later nonlinear voltage
conditioning then acts on an altered distribution. The repair carries a
continuous conditional SOC mean and variance: physical health-path mixtures
contribute variance, but a known charge translation does not.

The exact first two mixture moments are followed by a conditional Gaussian
projection and first-order OCV conditioning. These remain explicit
approximations. Health, thermal response, initial-SOC component identities and
joint RC/hysteresis nuisance candidates remain coupled. See the
[derivation and scope](analysis.md) and [implementation](history.py).

[Qualification](qualification002/result.json) passes **168 checks**. Across six
frozen eight-event fixtures, an unmerged continuous-path oracle gives maximum
query differences of 0.000367% Q and 0.000149 SOC points for the repair, versus
5.54% Q and 5.59 SOC points for the old grid. These are approximation comparisons,
not truth error. No further precision tuning was performed.

The [first attempt](qualification001/result.json), including two failed checks,
is preserved. Its range-failure test accidentally mutated a NumPy copy; the
[separate repair receipt](qualification_repair.json) records the test correction.
The estimator itself did not change between those qualification attempts.

## Whole-stream findings

Both cases have 90 minutes of cycling, 90 minutes of zero-current weak use,
and 60 minutes of renewed cycling. Temperature varies from 17 to 33 °C;
voltage noise has a declared 4 mV standard deviation. The aging stress imposes
a 15% reference-capacity loss and 15% reference-R0 rise at one hour. This is an
accelerated change within the finite hypothesis support, not realistic aging
calibration. Truth is confined to the generator/scorer; the estimator receives
the same public prior and assumed aging kernel in both cases.

| Binary32 log-weight result | Stationary | Monotone stress |
|---|---:|---:|
| Accepted observations | 504,000 | 504,000 |
| Last observation outside either preferred point-error scale | 6 min 30.74 s | 60 min 15.03 s |
| Maximum Q error during 90-minute weak use | 0.00706% | 0.00844% |
| Maximum SOC error during weak use | 0.000894 points | 0.001170 points |
| Maximum Q error after renewed loading | 0.1037% | 0.1115% |
| Maximum SOC error after renewed loading | 0.000724 points | 0.000799 points |
| Maximum Q difference from binary64, entire stream | 0.00000880% | 0.00001391% |
| Maximum SOC difference from binary64, entire stream | 0.0000000314 points | 0.0000000314 points |

All observations in the weak-use and renewed-loading phases meet both preferred
scales. Initial capacity learning has larger errors, and the aging jump creates
a transient; small final errors do not erase these. About 15.1 simulated seconds
after the supported jump, both targets hold for the rest of this particular
replay. This is not a general parameter-convergence time: there are only three
capacity levels and three R0 levels, and the changed values belong to them.

Binary32/binary64 standard-deviation ratios at saved checkpoints stay within
approximately 0.999947–1.000022 for Q and 0.9999987–1.0000023 for SOC. This shows
preservation of the reference's uncertainty, not validated statistical coverage.
The full sample metrics and checkpoint uncertainty comparisons are in the
[review](review001/result.json). The [plot](review001/long_run_errors.png)
uses saved checkpoints; extrema and gate decisions use every observation.

The fixed-span log16 arm explicitly stops at observation index 9,532 in each
case. No clipping, tail deletion, evidence reset or automatic span change hides
the failure. The other arms continue. Log-weight spans ultimately reach about
25,258 and 57,453 nats; the old codec supports only about 710 nats. Dynamic range,
rather than extra point accuracy, is the immediate encoding concern.

## Storage, execution and remaining limits

| Retained numeric layout | Bytes |
|---|---:|
| 729 binary32 log weights | 2,916 |
| Two binary64 SOC moments per hypothesis | 11,664 |
| Partial packed payload | **14,580** |
| Live decoded primary arrays in Python | 17,496 |

The prototype also retains its encoded packet, operator state, bounded kernel
cache and update workspace. Therefore 14,580 B is a **partial payload estimate**,
not actual total SRAM; even this estimate exceeds 10 KiB. The 729-hypothesis
count is constant throughout the run, and raw observations are not retained
inside the estimator. Saved input files and checkpoints belong to the harness.

The paired-arm four-hour replays took 231.4 and 233.0 host wall seconds, about
7 minutes 44 seconds total for eight simulated hours. This includes reference
comparison and scoring. It is not directly comparable to the original rolling
C estimator's timing and is not an M23 performance measurement.

No application-scale history degradation was observed in these two controls.
However, the cumulative weight log-distortion ledger reaches about 682 and 879;
it supplies no useful uniform lifetime bound here. Once quantization also
changes subsequent conditional moments, a weight-only bound does not certify
the entire continuous distribution. Finite support, Gaussian projection,
first-order OCV conditioning, uncalibrated aging, sensor assumptions, and
unchanged RC-branch capacitances also limit this result. Four hours cannot
establish ten-year stability or general-cell accuracy.

The next useful step is a small system comparison under off-support cell
parameters, gradual aging, varied loads/noise and long weak intervals. Define
the rolling/history boundary and observation ownership before adding feedback:
a posterior and the observations that produced it cannot be counted as
independent evidence. Compare against rolling-only behavior on the same streams,
then optimize the storage and execution costs that actually limit that system.
Further polishing of these already-small codec point errors is not a priority.

## Reproduction and provenance

Source revision, dirty-source hashes, commands and snapshots accompany the
[qualification](qualification002/reservation.json) and
[campaign](campaign001/reservation.json). Original C model sources are unchanged.
The [summary](summary.json) and [verification](verification.json) bind the saved
evidence, including earlier artifacts and the failed qualification attempt.

From the repository root, use new output directories; do not overwrite the
preserved attempts:

```sh
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python3 -B -m experiments.continuous_soc_001.qualify experiments/continuous_soc_001/qualification003
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python3 -B -m experiments.continuous_soc_001.campaign prepare experiments/continuous_soc_001/campaign002
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python3 -B -m experiments.continuous_soc_001.campaign run experiments/continuous_soc_001/campaign002
```

The first command reruns targeted qualification; the next two generate and run
both four-hour cases. `review.py` reviews the preserved `campaign001`; its
`review001` output already exists. `closeout.py` verifies saved evidence without
rerunning inference.
